09 Key Findings & Gaps
!

TS demuxer is H.264/H.265 + AAC only. Backend ts_demux.rs only matches stream types 0x1B, 0x24, 0x0F, 0x15. All other codecs in TS containers hit _ => {} (line 149) and are silently dropped.

ts_demux.rs:136-149
!

mpegts.js auto-detects more codecs than the backend. mpegts.js v1.8.0 supports H.264, H.265, AV1, AAC, MP3, AC-3, E-AC-3, Opus. AV1 and Opus are detected via PES private data registration descriptors ("AV01", "Opus"), not standard stream_type values. This creates an asymmetry: mpegts.js may play codecs the backend fMP4 pipeline can't.

node_modules/mpegts.js/src/demux/ts-demuxer.ts:779-815
!

MKV/WebM MediabunnyTransmuxer is dead code for playback. initTransmuxerPlayer (line 3580) rejects all non-TS formats. Full transmuxing code exists but is only active for thumbnail extraction.

useMSEPlayer.ts:3580, MediabunnyTransmuxer.ts:78-84
!

mp4parse is a dead Cargo dependency. Listed in Cargo.toml (0.17) but zero use statements found in any .rs file. Verified: grep -rn "mp4parse" --include="*.rs" → exit code 1 (no matches).

Cargo.toml:47, grep verified
!

5 player classes are dead code. FastStreamClient is never instantiated (0 new FastStreamClient results). MP4Player, HLSPlayer, DirectVideoPlayer, and PlayerModes are only used by FastStreamClient. The active playback path goes entirely through useMSEPlayer.ts.

FastStreamClient.ts:34, search verified
✓

ffmpeg remux uses stream copy, not transcoding. -c:v copy -c:a copy preserves any codec. The limitation is on the browser's native decoder, not ffmpeg.

server.rs:1981-1983, 2084-2086, 2182-2183
!

No WASM video codec decoders. All decoding is browser-native via MSE/hardware pipeline. jassub WASM is for subtitles only. No ffmpeg.wasm installed.

Verified: no .wasm video decoders in project

useMSEPlayer.ts:4295-4306

useMSEPlayer.ts:4329-4331
