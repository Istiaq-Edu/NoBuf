Implemented Fixes — What Changed & How to Test

L1: Health Endpoint — Version Removed

What changed: The /api/v1/health endpoint no longer returns the app version. The version field is now null instead of env!("CARGO_PKG_VERSION"). The health endpoint is public (no auth required) — leaking the version helps attackers target known CVEs.

What you'll see: curl http://127.0.0.1:8550/api/v1/health returns {"status":"ok","version":null} instead of {"status":"ok","version":"0.1.0"}.

How to test: curl http://127.0.0.1:8550/api/v1/health → version should be null.

L2: CSP Tightened — 5 New Directives + Scoped Ports

What changed: The Content Security Policy has been significantly tightened:

  • default-src restricted to 'self' only (was http://localhost:*)
  • connect-src scoped to ports 14201, 14200 (was http://localhost:*)
  • media-src scoped to ports 14201, 14200 (was http://localhost:*)
  • Added: object-src 'none' — blocks Flash/plugins
  • Added: base-uri 'self' — prevents <base> injection
  • Added: form-action 'self' — prevents form data exfiltration
  • Added: frame-ancestors 'none' — prevents framing
  • Added: font-src 'self' — prevents @font-face localhost probing

What you'll see: No visible change for normal app usage. The app can no longer connect to arbitrary localhost services or be framed/embedded by other applications.

How to test: Play a video → should work (port 14201 is allowed). Open DevTools console → should show no CSP violations during normal use.

L3: FragmentStore Error Logging

What changed: The silent catch (e) { } in FragmentStore's writeToDB now logs console.warn('[FragmentStore] IndexedDB write failed, memory-only:', e) instead of swallowing the error silently.

What you'll see: If IndexedDB writes fail (quota exceeded, corrupted DB), you'll see a warning in DevTools console instead of silent degradation.

How to test: Play a video → check DevTools console → should see no warnings during normal playback. If IndexedDB is full, you'll see the warning.

L4: CacheSessionContext Stale Closure Fix

What changed: getCacheInfo now reads from cacheMapRef.current (a ref that always points to the latest state) instead of cacheMap directly. The callback now has empty deps [] instead of [cacheMap], making it stable across renders.

What you'll see: The green cache progress bar should now correctly show cache status for videos. Previously, components using getCacheInfo in effects with [] deps would always see an empty cache (stale closure).

How to test: Play a video → the green cache bar should appear and update correctly. Switch between videos → cache info should update for each video.

L5: ErrorBoundary Reset on Route Change

What changed: Added componentDidUpdate to ErrorBoundary that resets hasError when the resetKey prop changes. Added optional resetKey prop to the interface.

What you'll see: If a component crashes and shows the error screen, navigating to a different part of the app (if resetKey is wired) will automatically clear the error and re-render. Previously, only a full page reload could recover.

How to test: This is a defensive fix — you won't see it unless a component crashes. The fix enables future recovery without reload.

L12: Dead Code Removed — cmd_report_cached_ranges

What changed: Removed the 58-line cmd_report_cached_ranges function from streaming.rs. It was defined as a #[tauri::command] but never registered in lib.rs, build.rs, or capabilities/default.json — completely unreachable dead code.

What you'll see: No visible change — the function was never callable from the frontend.

L13: Linux VPN Detection — Added operstate Check

What changed: The Linux VPN detection now checks /sys/class/net/<name>/operstate for "up" before reporting VPN active. Falls back to checking /sys/class/net/<name>/carrier for interfaces without operstate (e.g., WireGuard).

What you'll see: On Linux, VPN detection no longer reports false positives for stale/disconnected VPN interfaces.

L14: macOS VPN Detection — Fixed Substring Match

What changed: Changed from stdout.contains(p) (substring match on entire output) to stdout.split_whitespace() + iface.starts_with(p) (prefix match on individual interface names). This prevents false matches like "funtube0" matching "tun".

What you'll see: On macOS, VPN detection is now more accurate — only matches interfaces that actually start with VPN prefixes.

L16: build.rs — .unwrap() Replaced with .expect()

What changed: .unwrap() on try_build() replaced with .expect("Failed to build Tauri application: check tauri.conf.json and capabilities"). Build failures now show a helpful message instead of a bare panic.

What you'll see: If the Tauri build fails (invalid config, missing capabilities), the error message is now actionable.
