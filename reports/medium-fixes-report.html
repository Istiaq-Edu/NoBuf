Implemented Fixes — What Changed & How to Test

M1: Stream Token — Constant-Time Comparison

What changed: All 8 token comparison sites in server.rs (6 sites) and hls/manifest.rs (2 sites) now use constant_time_eq::constant_time_eq() instead of ==. The dependency was already in Cargo.toml (used for API key verification) — just wasn't applied to stream tokens.

What you'll see: No visible change — all valid tokens still work, invalid tokens still rejected. The fix prevents timing side-channel attacks that could theoretically recover the token byte-by-byte.

How to test: Play a video (streaming uses token) → should work normally. The token validation is identical in behavior, just constant-time in execution.

M6: Added [profile.release] to Cargo.toml

What changed: Added release profile with lto = true, codegen-units = 1, strip = "symbols", overflow-checks = true.

What you'll see: Production builds will be ~10-20% smaller (LTO + strip), ~5-15% faster (LTO + single codegen unit), and will detect integer overflows (overflow-checks). Debug builds are unaffected.

How to test: cargo build --release → should compile (slower than debug due to LTO). Check binary size — should be smaller than before. file target/release/app_lib → should show "stripped".

M7: dropConsole in Vite Production Build

What changed: Added build: { sourcemap: false, dropConsole: true } to vite.config.ts. This removes all console.* calls from the production JS bundle.

What you'll see: In production builds, no console.log output will appear in DevTools. In development mode (npm run dev), console logs still work normally.

How to test: npm run build → check dist/assets/*.js with grep for "console.log" → should find 0 matches. Run npm run dev → console logs should still appear.

M16: Atomic Config Writes

What changed: Both api_settings.json and network_settings.json now use the atomic write pattern (write to .tmp, sync_all(), then rename()) instead of direct std::fs::write(). If the app crashes mid-write, the old file is preserved — no truncated JSON.

What you'll see: No visible change. If the app crashes while saving settings, the previous settings are preserved instead of being corrupted.

How to test: Change API settings → should save normally. Change network settings → should save normally. Restart app → settings should persist.

M18: File Permission Hardening (Unix)

What changed: After opening the Telegram session file, the app now sets permissions to 0o600 (owner read/write only) on Unix systems. WAL and SHM files are also restricted.

What you'll see: On Linux/macOS, the session file is now only readable by the current user. On Windows, this is a no-op (Windows uses ACLs, not Unix permissions).

How to test: On Linux: ls -la ~/.local/share/com.istiaq.nobuf/telegram.session → should show -rw------- permissions.

M19: Log Level Changed to Warn in Release

What changed: In release builds, the default log level is now warn instead of info. In debug builds, it remains info.

What you'll see: In production, only warnings and errors will appear in logs — not info-level messages. This reduces log noise and prevents sensitive info-level messages from appearing in production.

How to test: Build in release mode → check console output → should only see warnings/errors, not info messages. Build in debug mode → info messages should appear.

M24: Content-Disposition Header Sanitized

What changed: The filename in the Content-Disposition header of API download responses now strips ", \r, and \n characters to prevent header injection.

What you'll see: No visible change for normal filenames. Files with quotes or newlines in their names will have those characters stripped in the download header.

How to test: Download a file via API with a normal name → should work. The header is now safe from injection even with malicious filenames.

Documented (Architectural — Can't Fix Without Major Refactor)

M2: Token in URL Query Parameters

The stream token is passed as ?token=... in all streaming URLs. This exposes it via Referer headers, server logs, and HLS playlist content. Fixing this requires migrating to custom headers (e.g., X-Stream-Token) which breaks <video src=...> that can't set custom headers. The nobuf-stream:// custom protocol is a partial workaround but doesn't cover all cases.

M4: Telegram Session Unencrypted at Rest

The session file is plain SQLite with the MTProto auth key in cleartext. Encrypting it requires wrapping grammers_session::storages::SqliteSession with an encryption layer, using OS keychain (DPAPI on Windows, Keychain on macOS). This is a significant architectural change.

M20: jassub WASM on Main Thread

jassub (WASM subtitle renderer) runs on the main thread, giving it DOM access. Migrating to a Web Worker would isolate it but requires testing with various subtitle formats (ASS, SSA, SRT, VTT).

M21: No Update Rollback

If an update installs but the new version crashes on startup, there's no automatic rollback. Implementing this requires a binary backup + canary flag + restore-on-crash mechanism. Tauri v2 doesn't provide built-in rollback.

M25: String Error Type

88 Result<_, String> signatures across 15 files. Migrating to a proper error enum (thiserror) would give structured error codes but is a large refactor that touches every command and every frontend error handler.
